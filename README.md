## 舵机 ID 与回读诊断（v2）

上电后、进入电机测试前，会先显示 **SERVO SCAN ID1-4** 页面（每轮循环都会刷一次），
逐个 ID 发 `POS_READ` 并显示收到的字节数 `RX` 和回读位置 `P`：

| 现象 | 含义 |
|---|---|
| `RX 00  P ---` | 该 ID 完全没有应答：TX/RX 接反、TTL 跳线在 USB 侧、波特率不对、或该 ID 不存在 |
| `RX >0  P ---` | 有字节回来但解析不出完整帧：通常是**多个舵机 ID 相同**，同时应答造成总线冲突 |
| `RX >0  P 305` | 正常，舵机回了位置（0~1000） |

> ⚠️ 如果 4 个舵机**同时一起动**，基本可以确定它们的 **ID 都是出厂默认的 1**。
> 需要逐个改 ID：一次只接一个舵机到 BusLinker，用 ServoStudio / Bus Servo Terminal
> 把 ID 依次改成 1、2、3、4（每改完一个换下一个），再全部接回。

v2 还改进了回读逻辑：发 `POS_READ` 前清空接收缓冲，最多等 30 ms 收包；同时在
USART1（Type-C「串口1」，115200）打印每次回读的原始字节（十六进制），方便排查。
## v4：回读（POS_READ）的关键修复

STM32 的 USART 只有 **1 字节接收寄存器、没有 FIFO**。HTS-35H 的应答帧约 8 字节，
在 115200 下全部到达只需 ~0.7 ms。v1/v2 里“等 1~10 ms 再去读”的做法会让除最后 1 字节
以外的数据全部被覆盖（overrun），所以永远解析不出帧、日志里显示 `servo=ERR`。

v4 改为发完 `POS_READ` 后**每 50 µs 紧循环轮询**接收（最多等 20 ms，收到完整帧立即结束），
并在全双工模式下完全收不到字节时自动切到**单线半双工模式**（适配 BusLinker 的 1-wire TTL）
再扫一次；扫描页标题会显示 `FD` 或 `HD`。
## 直行 / 原地转 90° 演示（当前固件）

上电后：舵机回中 → 陀螺仪零偏校准（约 0.6 s，车必须静止）→ 开始循环：

```
直行 1.5 s (PWM 3500) → 停 0.7 s
原地转 +90°          → 停 0.7 s
直行 1.5 s           → 停 0.7 s
原地转 -90°          → 停 0.7 s
（循环）
```

原地转的实现：前轮舵机 +45°、后轮舵机 -45°（反向偏转），四轮同时驱动，
靠 ICM-20948 的 Z 轴陀螺积分判定角度，到 90° 即停；前 300 ms 会自动检测
旋转方向，方向反了会自己反打电机。超时保护 6 s。

### 标定常量（`USER/main.c` 顶部）

| 常量 | 当前值 | 说明 |
|---|---|---|
| `MOTOR_DIR[4]` | `{-1,+1,-1,+1}` | 让该轮“向前”的 PWM 符号；若直行时某轮反转，改对应项 |
| `SERVO_DIR[4]` | `{+1,+1,+1,+1}` | 舵机转向方向符号；若左右转向相反，改对应项 |
| `SERVO_TRIM[4]` | `{0,0,0,0}` | 舵机机械中位微调（单位：0.24°） |
| `GYRO_SIGN` | `+1` | 陀螺仪偏航符号；转角不准/超时可尝试取反 |
| `TURN_STEER_DEG` | 45° | 原地转时前后轮反向偏转角（受机械限位限制，别设太大） |
| `STRAIGHT_PWM` | 3500 | 直行速度 |
| `TURN_PWM` | 4200 | 原地转速度 |
