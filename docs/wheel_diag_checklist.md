# RL 轮（左后 / MotorC / E3）PWM 异常排查清单（T1）

> 适用：`C30D_MotorTest` 固件基线 `main`（2026-11-20）。配套工具 [`tools/wheel_diag.py`](../tools/wheel_diag.py)。
> 依据：[PROGRESS.md](../PROGRESS.md) §5 阻塞项 1、[TASKS_SPRINT1.md](../TASKS_SPRINT1.md) T1、[README.md](../README.md) §1/§7。
> 本清单由用户（现场硬件操作者）执行；固件/日志/串口由 Lead 负责。

## 1. 现象与判据

2026-11-18 抓到的日志（`G` 70 cm，`tgt=900`）：

```
SPD FWD tgt=900 1007/3278 926/3784 428/4335 998/3418 YAW=-2 C=0 SVO=0 P=5 CMD=G
SPD FWD tgt=900 914/2207 938/2478 835/5238 927/2314 YAW=-12 C=-2 SVO=0 P=5 CMD=G
SPD FWD tgt=900 929/1864 955/2034 947/5499 885/1959 YAW=-18 C=-3 SVO=0 P=5 CMD=G
```

- 同样实测速度（约 950 counts/20 ms）下，起步瞬态之后（第 2、3 行）RL（第 3 对数字）PWM 仍约 **5200–5500**，其他三轮约 **1900–2500**；
- RL 实测速度本身还在 **428 / 835 / 947** 之间跳变（`cv%` 约 30%），其他轮稳定；
- yaw 持续负向增大，对应**车持续右偏**。

速度环是**每轮独立 PID**：同样的实测速度要 2 倍 PWM，只有两种解释——

1. **编码器少计数/漏计数**：PID 以为轮子慢，继续加大 PWM（历史上该轮就出现过 −3519/−161/−7607 的计数抖动）；
2. **该轮电机/机械负载大**：同样 PWM 转速低，PID 只能加大 PWM 追赶。

**T1 验收判据**（2 m 直行）：
- 四轮 PWM 偏差 `(max−min)/median` **≤ 20%**；
- yaw 漂移 **|°/m| ≤ 2**。

> 提醒：20% 是「相对中位数」的偏差。航向闭环会在左右轮上**主动**制造差速（日志 `C` 越大差越大，约 `5×|C|` PWM），`C` 很大时 PWM 偏差有一部分是正常修正，不是轮子故障；`wheel_diag.py` 会给出 `C` 统计并在 warnings 里提示。

## 2. 安全须知（先读再做）

- **换线一律断电**（拔电池/急停），不要带电插拔 6pin——编码器 5V 与电机线共插头，带电插拔可能烧驱动或编码器。
- 开环 `O<n>` 测试会直接驱动电机，**必须四轮离地、垫木/支架架稳**，人不要站在车前后。
- 首次上电后**静止 ≥0.6 s**（IMU 零偏标定），否则 yaw 基准不对。
- 手转轮子检查前必须断电，避免反电动势/误动作。
- 地面 2 m 测试留 ≥2.5 m 净空，人站侧面；串口/无线 `S` 停车指令常备。
- `F/B/O` 模式有 **5 s 指令看门狗**：5 s 内没有新指令会自动停（见 §7 的应对）。
- 电池电量不足会让所有轮 PWM 普遍升高、转速不稳；**先确认电池电压正常**再判读绝对 PWM 值。相对偏差（vs 中位数）受电量影响小。
- **一次只改一个变量**，每次改完立即记录（§9）。

## 3. 5 分钟快检（按顺序）

1. **目视 RL 轮**：有无草/绳/胶带缠绕，轮胎是否蹭车架，轮毂螺丝是否松，编码器磁环/码盘是否松动偏心，6pin 插头是否退针/歪针/发黑氧化/锁扣没到位，线束是否被压住或拉扯。
2. **手转对比**：断电架车，手转 RL 一圈，与其他三轮比较阻力和声音。卡滞/沙沙声/轴向间隙 → 机械（轴承、减速箱、轮子）。
3. **开环 `O2500`**：四轮悬空 2–3 s，看 OLED/日志四轮实测速度（§4），然后 `S`。
4. **重插 MotorC 6pin**（§5）。
5. 仍异常 → **C/D 对调**（§6）。
6. 修好后按 §7 做 2 m 复测，§8 用工具出结论。

## 4. 开环 O 测试：先分清「编码器」还是「电机/机械」

命令：`O2500`（范围 0–12000，四轮同一 PWM，开环），2–3 s 后 `S`。建议再补一次 `O1500`。
日志会变成 `OL PWM=2500 tgt=... <四轮实测速度>/2500 ...`，**OL 行不参与 T1 的 PASS/FAIL**，但可以对比「同 PWM 下四轮转速」：

| 悬空 `O2500` 现象 | 判读 |
|---|---|
| 四轮转速接近（偏差 <15%），但闭环时 RL PWM 仍是 2 倍 | **编码器少计数/接触不良**（或编码器线序/CPR 问题） |
| RL 明显转得慢（同 PWM 下低 30% 以上） | **电机/减速箱/轴承/轮子拖滞** |
| RL 转速忽高忽低、偶尔跳 0 | **编码器接触不良**（最符合当前症状） |

工具支持把 OL 行汇总成「等 PWM 速度对比」：

```powershell
python tools\wheel_diag.py .\logs\o2500.log --include-open-loop
```

记录：每次 `O` 测试至少保留 3 行日志，标注电池电压。

## 5. 重插 MotorC 6pin（标准动作）

1. 断电（拔电池），等 10 s；
2. 拍照记录插头方向、线序、锁扣位置；
3. 拔下板端 **MotorC** 6pin（对应编码器 **E3**，即左后轮）；6pin 是电机 M+/M− 与编码器 VCC/GND/A/B 共用线束（以板端丝印为准）；
4. 检查针脚：退针、弯针、发黑氧化、插头内异物、线皮破损；必要时用电子清洁剂/轻刮氧化（断电、别弯针）；
5. 插回，锁扣到位，轻拉线确认不松；
6. 上电 → 静止 0.6 s → 悬空 `O2500` 2–3 s → `S`，记录；
7. 落地按 §7 跑 2 m，`S` 后抓日志，用 `wheel_diag.py` 判定。

**通过条件**：PWM 偏差 ≤20% 且 |yaw| ≤2°/m，且连续 3 次稳定。否则进 §6。

## 6. MotorC ↔ MotorD 对调矩阵

**关键前提**：6pin 把电机与编码器捆在一根线束上，所以「对调」= 整根线束 + 物理轮一起换通道。日志字段是**按通道**命名的：

- `RL` 字段 = **MotorC 通道**（现在插在 C 上的轮子，不管它原来在哪）；
- `RR` 字段 = **MotorD 通道**。

步骤：
1. 断电，两个 6pin 在板端互换（C↔D）；
2. 上电，静止 0.6 s；悬空 `O2500` 2–3 s（对比同 PWM 转速），`S`；
3. 落地低速短距离（`V600` + `F`，1–2 m 内 `S`，注意车会往原方向偏，留足空间）；
4. 抓日志，`wheel_diag.py` 看**高 PWM 落在哪个字段**。

| # | 对调后现象 | 判读 | 下一步 |
|---|---|---|---|
| 1 | 高 PWM 从 `RL` 字段移到 **`RR` 字段**（跟着物理轮走） | 故障在「该物理轮 + 它自己的线束/编码器/电机」，与主板通道无关 | 进 §6.1 再分编码器/电机 |
| 2 | 高 PWM **仍在 `RL` 字段**（跟着通道 C 走，现在驱动的是原来正常的 RR 轮） | 故障在**主板 MotorC 通道 / 驱动 / E3 编码器接口** | 检查/更换驱动板 C 通道（软件补偿需 Lead 评估，不能替代硬件修复） |
| 3 | 两轮都恢复正常 | 原 6pin **接触不良**，重插/换位后恢复 | 记录，连续 3 次复测确认稳定 |
| 4 | 两边都异常或出现新异常 | 操作中插错/线束损坏 | 断电复查插头，恢复原线序重测 |

> 对调后物理轮位置变了（左后轮改由 D 通道驱动），车会偏得更厉害；地面测试只用低速、短距离，以悬空 `O` 测试为主。

### 6.1 若故障「跟着物理轮走」，再分编码器 vs 电机/机械

- 若线束可拆分（电机 2pin + 编码器 4pin 分别插板）：**只交换编码器插头**（C↔D 的编码器端），再看高 PWM 跟谁走：
  - **跟编码器线走** → 编码器/编码器线/插头（最常见，与历史计数抖动一致）；
  - **跟电机走** → 电机/减速箱/机械。
- 若不可拆分：用 §4 的 `O` 测试判据——同 PWM 转速正常但闭环 PWM 高 → 编码器；转速明显低 → 电机/机械。
- 手转一圈看 OLED 实测速度量级：其他轮差不多、该轮明显偏小 → 编码器少计数（OLED 每 200 ms 刷新，看量级即可）。

**更换顺序建议**（成本从低到高）：6pin 线束 → 编码器/电机总成 → 驱动板通道。

## 7. 2 m 直行复测流程（T1 验收）

固件 `G` 只跑 **70 cm**，2 m 用 `F` + `S` 手动控制。注意 **5 s 指令看门狗**：`F` 之后 5 s 没有新指令会自动停车，所以 2 m 途中必须周期性地发**无状态副作用**的指令刷新看门狗——用 `V900`（只改目标速度，不会重置 yaw 积分/PID；重复发 `F` 会 `yaw_deg=0` 并重置速度环，**不要**这么做）。

1. 场地：平整地面，胶带标 **0 m / 1 m / 2 m** 三条线，量尺对齐；清理障碍；
2. 上电，**静止 0.6 s** 等 IMU 标定；发 `C` 舵机回中；发 `V900`；
3. 起点摆正（车身/轮子对齐 0 m 线），发 `F` 起步；
4. 每 2–3 s 发一次 `V900` 保活（目标速度不变，yaw 积分连续）；
5. 车头过 2 m 线立刻发 `S`；
6. 用卷尺记录：实际行驶距离、车头中心相对直线的**横向偏差**（cm）；
7. 抓串口日志：从 `F` 之前开始，到 `S` 之后 1–2 行结束；存到项目根目录或自建 `logs\` 目录，命名 `run2m_YYYYMMDD_HHMM.log`；
8. **重复 3 次**（每次重新摆正、重新上电或至少重新对齐），3 次都 PASS 才算 T1 通过；取最差一次作为验收证据。

日志与判读注意：

- 每秒 1 行；`V900` 下 2 m 约 **11 行**（18 cm/s）。行数明显偏少 → 丢数据或没跑够 2 m；
- 三个串口（USART1/3、UART5）会打印**同样内容**，只抓一个口；同时抓两个口会让行数/里程翻倍、yaw 漂移被低估一半，判定失真；
- 最后的 `SPD STOP` 行工具自动排除，不用手工删；
- 若混入 `OL PWM=` 行，默认不参与判据（需要时加 `--include-open-loop`）；
- 工具估算里程来自编码器；RL 少计数会让 2 m 被低估（可能 1.7–1.9 m）。**以卷尺实测为准**，差异本身就是编码器问题的证据；
- 行间隔不是 1 s（抓包工具合并/丢行）时用 `--period-ms` 给实际平均间隔，否则 yaw 漂移会成比例失真。

## 8. 用 wheel_diag.py 出结论

在项目根目录执行（PowerShell）：

```powershell
Set-Location 'C:\Users\iheat\Desktop\smart wheels2\C30D_MotorTest'

# 文本报告（默认）
python tools\wheel_diag.py .\logs\run2m_20261121_01.log

# JSON（存档/对比；工具输出全是 ASCII，utf8 保存即可）
python tools\wheel_diag.py .\logs\run2m_20261121_01.log --json | Out-File -Encoding utf8 run2m_20261121_01.json

# 带开环 O 测试对比
python tools\wheel_diag.py .\logs\run2m_20261121_01.log --include-open-loop

# 工具自检（35 项，应全部 PASS）
python tools\wheel_diag.py --selftest
```

输出解读：

| 输出项 | 含义 | 判读 |
|---|---|---|
| `mean_spd` | 每轮平均实测速度（counts/20 ms，FWD/BACK 行） | 四轮应接近目标；RL 偏低说明实际转慢了 |
| `cv%` | 该轮速度变异系数 | >10% 提示编码器接触不良/打滑 |
| `mean_pwm` | 每轮平均 PWM | 绝对值受电池电压影响，重在看相对值 |
| `vs_med` | 相对四轮 PWM 中位数的百分比 | 核心异常指标：RL 应接近 0%，异常时 +80% 以上 |
| `pwm/spd` | PWM ÷ 实测速度 | **最能定位「同速要 2 倍 PWM」**：正常 2.5–3.0，异常 6+ |
| `pairs` | 左/右、前/后平均 PWM | 区分「单轮故障」还是「航向修正导致的左右差」 |
| `PWM spread` | `(max−min)/median`，判据 ≤20% | [PASS]/[FAIL] |
| `Yaw drift` | 净 yaw 变化 ÷ 估算里程；判据为绝对值 ≤2°/m | 同时给出回归斜率、最大分段漂移（仅供诊断，不参与判据） |
| `VERDICT` | 总判定 | 退出码 0 = PASS，1 = FAIL/数据不足，2 = 用法错误 |
| `! warnings` | 点名可疑轮、里程不足、目标速度变化、`C` 过大等 | 先看 warnings 再下结论 |

常用参数：

- `--period-ms 1000`：日志行间隔（默认 1000 ms）；
- `--ref-wheel mean|FL|FR|RL|RR`：里程用哪个轮估算，默认四轮平均；`--ref-wheel RL` 可量化 RL 少计数对里程的影响（两次里程差 ≈ RL 少计比例）；
- `--direction fwd|back`：只分析一个方向（日志混了 F/B 时用）；
- `--include-open-loop`：附带 O 测试等 PWM 速度对比（不参与 PASS/FAIL）；
- `--pwm-limit` / `--yaw-limit`：自定义阈值（默认 20 / 2.0）。

## 10. 决策树与推荐下一步

```
重插 MotorC 6pin → 悬空 O2500 记录 → 落地 2 m 复测
 ├─ PASS（PWM ≤20% 且 |yaw| ≤2°/m）→ 连续 3 次 PASS → 交 Lead 打 tag t1-wheel
 └─ FAIL → MotorC ↔ MotorD 对调 → 悬空 O2500 + 短距低速（V600，1–2 m）复测
      ├─ 高 PWM 跟着物理轮走（RL 字段 → RR 字段）
      │     ├─ O 测试同 PWM 转速正常 → 编码器/编码器线/插头（优先换线束）
      │     └─ O 测试转速明显低 → 电机/减速箱/轴承/轮子拖滞（拆检/换电机）
      └─ 高 PWM 跟着通道 C 走（仍在 RL 字段）
            → 主板 MotorC 通道/驱动/E3 接口异常（换驱动板；软件补偿另议）
```

**给用户的第一动作（推荐）**：断电 → **重插 MotorC 6pin** → 上电静止 0.6 s → 悬空 `O2500` 2–3 s 记录 → 落地按 §7 跑 2 m → 日志交 Lead 跑 `wheel_diag.py`。
若重插无效，再做 **C/D 对调**：这一步能一次性把「轮子侧故障」和「主板通道侧故障」分开，避免盲目换件。
