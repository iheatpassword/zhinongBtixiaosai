# 第 4 路激光（垄侧测距）协议与控制约定

> 状态：C30D 侧代码已就绪并**只编译、未烧录**（板上仍是 `b718475` 纯航向版）。
> 等你把 F103 硬件/固件加好、上车确认后，再一起烧录测试。

## 1. 用途

在**前轮附近、面向车所跨的那条垄**加一路激光，测「车到垄侧壁」的距离。
它直接给出**横向偏移量**，与 IMU 航向解耦：

- 航向：IMU + 前后轮差速（已验证，100 cm 漂移 ≤0.6°）；
- 横向：`dRidge` → 四轮同向小偏角 δ（90°±δ），不改变航向。

## 2. 接线

- 传感器接 F103 的新通道（UART/ADC 均可，按你现有 F103 固件框架）；
- F103 → C30D 仍走**原来的 UART4**（F103 TX → PC11，RX ← PC10，GND，115200 8N1）；
- 建议供电独立/加滤波，避免与电机共地噪声（之前右激光间歇掉数据就是供电/接触问题）。

## 3. 帧格式（新增，与主帧共存）

主帧保持不变（10 字节）：

```
AA 55 | dL(2) dR(2) dF(2) | flags | CRC8
```

新增**辅助帧**（6 字节）：

```
AA 56 | id(1) | d(2) | flags(1) | CRC8
```

| 字段 | 说明 |
|---|---|
| `AA 56` | 辅助帧同步头（`56` 与主帧 `55` 区分） |
| `id` | 传感器编号，`id=1` 表示垄侧激光（预留 2、3…） |
| `d` | 距离，**mm，小端**；`0xFFFF` 表示无效 |
| `flags` | bit0 = 本帧有数据；其余保留 |
| `CRC8` | 多项式 `0x07`、初值 `0x00`，覆盖 `AA,56,id,dLo,dHi,flags` 共 6 字节 |

发送频率：**10~50 Hz** 均可（C30D 侧 100 ms 超时判失效），建议与主帧同频或略低。

## 4. C30D 侧实现（已完成，未烧录）

- `LaserData` 新增：`dRidge`、`ridge_flags`、`ridge_valid`、`ridge_ms`；
- 解析器同时识别 `AA 55` 主帧与 `AA 56` 辅助帧，CRC 分别校验；
- 100 ms 收不到辅助帧 → `ridge_valid=0`；
- 日志新增字段：`RG=dRidge,ridge_flags,ridge_valid`（`-1` 表示无效）；
- 控制（仅在 `ridge_valid` 时生效）：

```
e = dRidge - RIDGE_TARGET_MM
δ = clamp(RIDGE_SIGN * RIDGE_KP * e, ±RIDGE_OFFSET_MAX)
四轮角度 = 90° + δ
```

当前参数：`RIDGE_TARGET_MM=120`、`RIDGE_KP=0.05`、`RIDGE_OFFSET_MAX=6°`、`RIDGE_SIGN=+1`。
传感器无效时 δ=0，自动退回纯航向保持（与现在行为一致）。

## 5. 标定与验收（硬件到货后）

1. **链路**：日志 `RG=` 数值持续刷新、`ridge_valid=1`，与卷尺读数一致（±2 mm）；
2. **静态标定**：把车正确跨垄摆好，读 `RG` 作为 `RIDGE_TARGET_MM`（当前暂定 120，按实车改）；
3. **方向**：手推车靠近垄壁（`dRidge` 变小），观察 δ 是否让车“远离”垄壁；反了就翻 `RIDGE_SIGN`；
4. **平移 100 cm**：`dRidge` 波动 ≤±15 mm，yaw ≤2°；
5. **平移 220 cm**（比赛行程）：不碰垄、不丢数据；
6. 通过后打 tag `p2-ridge-sensor`。

## 6. 需要你确认

1. F103 新通道：UART 还是 ADC/IO？引脚？发送频率？
2. 传感器安装：在前轮附近，朝**车所跨垄的侧壁**（垂直距离），安装高度/量程是否覆盖 30~300 mm？
3. 车正确居中时，传感器到垄壁的**大致距离**（用来定 `RIDGE_TARGET_MM`，先给个估值即可）。
